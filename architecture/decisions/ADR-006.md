# ADR-006: Gemma 4 31B for workers, Gemini 3 Flash for the reviewer

**Status:** Superseded by [ADR-011](ADR-011.md) (2026-11-21). Kept for the record.

## Context
The only model access is a free Gemini API key. The free tier has per-minute request and token
limits and no billing, which also acts as a hard $0 spending cap (the assignment asks for one).
Measured on 2026-11-21 from this key: `gemma-4-31b-it` answered in ~20 s; `gemini-3-flash-preview`
in ~2 s; `gemini-2.5-flash` is retired for new users (404); `gemini-flash-latest` and
`gemma-4-26b-a4b-it` returned 503 (high demand). A reviewer on the same model as the builder tends
to share its blind spots.

## Decision
- Analyst, Builder, Tester: `gemma-4-31b-it`. On 429/503: exponential backoff, then fall back to
  `gemma-4-26b-a4b-it`.
- Reviewer: `gemini-3-flash-preview`. A different model family from the workers (proprietary Gemini
  vs open-weights Gemma), so its errors are less correlated with the Builder's.
- Model ids are configuration (workflow `env`), recorded in every `usage.json` with token counts.

## Alternatives considered
- **Gemini Flash for every role.** Faster and stronger, but then the reviewer shares the worker's
  model, which weakens ADR-008, and all roles compete for one model's rate limit. Rejected.
- **Gemini Pro for the reviewer.** Stronger, but free-tier Pro limits are much tighter and a
  stalled review blocks the run. Rejected for now; revisit if the reviewer misses seeded defects.
- **A paid Claude or OpenAI model.** Better tool use, but needs billing we do not have. Rejected.

## Consequences
- Total cost is $0; tokens are still reported per run from `usage.json`.
- Gemma is slow (~20 s/call), so a full build with 25-step agents can take 10+ minutes; job
  `timeout-minutes` must allow for that.
- The reviewer is stronger than the workers. That is the intended asymmetry (checking should be
  harder to fool than building), but it can also make the reviewer request many changes; the
  evidence gate (ADR-008) limits unfounded ones.
- Preview models can change or disappear; fallbacks and config ids make swapping cheap.
