# ADR-003: Hand-offs pass named artifacts, and each role gets only the ones it needs

**Status:** Accepted (2026-11-21)

## Context
What an agent receives decides what it can get wrong and what it can be tricked by. Passing
everything (full transcripts, all artifacts, the raw issue) maximises context but spreads
untrusted text to agents with write access and lets the reviewer read the implementer's reasoning,
which the assignment forbids. In A2, giving the agent `ARCHITECTURE.md` helped it place changes
correctly, so curated documents are worth passing.

## Decision
Agents exchange files, never conversations. Inputs per role:

| Role | Receives | Deliberately withheld | Why withheld |
|---|---|---|---|
| Analyst | raw issue (in `<untrusted_issue>` tags), condensed A1 skill, A2 `ARCHITECTURE.md`, read-only repo | nothing | it is the role built to read untrusted text |
| Builder | `spec.md`, `design.md`, repo | raw issue | injection quarantine: the agent with write tools never reads attacker text |
| Tester | `spec.md`, repo with the change | Builder transcript, `design.md` rationale | tests should come from the requirement, not from how it was coded |
| Reviewer | raw issue, `git diff base...head` computed by the harness, repo at PR head | `spec.md`, `design.md`, `test_report.md`, PR body, all transcripts | independence (ADR-008); also lets it catch spec drift |

On a test failure the Builder gets the failing test output (trimmed), not the Tester's transcript.
On a review round, `rework_1` gets the review findings and the earlier spec and design.

## Alternatives considered
- **Shared full transcript.** Most context, but it leaks untrusted text and reasoning everywhere.
  Rejected.
- **LLM-written summaries between stages.** Shorter, but a summary is another place an injection
  or a misreading can be laundered, and it is not checkable. Rejected in favour of structured
  artifacts that pass a gate.
- **Give the Reviewer the spec.** Easier review, but the Reviewer then checks the code against the
  Analyst's reading of the issue instead of the issue, and it inherits the workers' framing.
  Rejected.

## Consequences
- Every hand-off is a file a human can open in the run's artifacts.
- The Builder can only be influenced by the issue through the spec, which is gate-checked and
  schema-shaped (ADR-007, ADR-009). That reduces injection risk but does not remove it: text can
  still travel inside an acceptance criterion.
- The Builder may lack nuance the issue had and the spec dropped.
