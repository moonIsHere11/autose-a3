# ADR-004: State lives in per-job Actions artifacts plus one run-ledger comment; the code branch carries only code

**Status:** Accepted (2026-11-21)

## Context
Stages run in different jobs on different VMs, so state must cross VM boundaries. A run can fail
mid-way (rate limits, timeouts) and must be restartable without repeating paid work. A maintainer
must be able to follow a run from GitHub alone. And whatever is stored where the reviewer can read
it is visible to the reviewer.

## Decision
- Each job uploads its outputs as named Actions artifacts (`spec.md`, `design.md`, `diff.patch`,
  `test_report.md`, `pr.md`, `review.md`, `transcript.jsonl`, `usage.json`). Later jobs download
  only the artifacts they are entitled to, by name (this is how the reviewer is denied the spec and
  design, ADR-003).
- One **run ledger** comment on the issue, created by `gate` and edited by each later job: a table
  of stage, status, check result and links (run, PR, review).
- `$GITHUB_STEP_SUMMARY` renders each job's artifacts on the run page.
- The code branch `autose/issue-N` carries only code and tests. No reasoning documents go on the
  branch.
- Restart: GitHub's "Re-run failed jobs" re-runs only failed jobs and reuses the artifacts of jobs
  that succeeded, so a restart resumes from the last passed job. A new trigger on the same issue
  starts from scratch, force-updates `autose/issue-N` and reuses the open PR.

**Amendment (2026-11-21, after real re-runs):** "Re-run failed jobs" was the restart story, and it partly held.
`build`/`ship_0` outputs were reused across attempts, and re-running only `review_1` worked several times after
provider outages. But a re-run of issue #1 broke at `rework_1`. The failed attempt-1 `review_1` had already uploaded
a partial `review-1` artifact (its upload step is `if: always()`), and in attempt 2 `rework_1` downloaded the stale
copy by name: `FileNotFoundError: review1/review.json`. Fix: artifacts that a re-runnable job produces *and* a
downstream job consumes are now named with `-a${{ github.run_attempt }}` (`review-1-a2`, `work-1-a2`). Artifacts of
jobs that are never re-run (`issue`, `work-0`) keep stable names so later attempts can still read them. Two more
lessons: a re-run executes the *original* commit's workflow YAML, so YAML fixes need a fresh trigger (`/autose`),
and every job now loads the harness from the default branch, so harness fixes *do* reach re-runs.

## Alternatives considered
- **Artifacts committed to the PR branch** (e.g. `.autose/issue-N/design.md`). Durable and
  versioned, but the reviewer checks out the PR head and would read the implementer's reasoning.
  They also pollute the diff a human merges. Rejected.
- **PR comments as the store.** Visible, but the PR does not exist until stage 5, and comments are
  readable by anyone with the token, including the review job. Rejected as the primary store; used
  only for the ledger and the review.
- **Actions cache.** Keyed and evictable, not meant for state of record. Rejected.

## Consequences
- Restart granularity matches Actions' own re-run granularity, so no custom resume code is needed.
- Artifacts expire (90 days by default). `results/runs.md` links to them and key artifacts are
  copied into the submission repo.
- Two runs on the same issue would race on the branch; handled by the concurrency group (ADR-010).
