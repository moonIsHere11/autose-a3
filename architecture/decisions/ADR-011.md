# ADR-011: Fast lite model for workers (Gemma as fallback), Gemini 3 Flash for the reviewer

**Status:** Accepted (2026-11-21). Supersedes [ADR-006](ADR-006.md).

## Context
ADR-006 put the three worker roles on `gemma-4-31b-it`. The first local end-to-end run of the
build pipeline (issue I5) showed the decision was wrong in practice, not in principle:
- The first Requirements call to `gemma-4-31b-it` never returned a usable answer: it returned
  HTTP 503 "model is currently experiencing high demand" and a direct probe a few minutes later
  took 41 s to fail with the same 503. With ADR-006's backoff (5, 10, 20, 40, 60 s per model) one
  stage could spend ~3 minutes waiting before it even fell back.
- A full build makes roughly 40-80 model calls (four agents, up to 16 steps each, plus retries).
  At ~20 s per successful Gemma call and frequent 503s, a single issue would need 20-40 minutes
  of wall time, far over a sensible job timeout, and five issues plus ten seeded reviews would
  not finish.
- In the same probe `gemini-3.5-flash-lite` answered in ~2 s and `gemini-3-flash-preview` in ~4 s
  (it is a thinking model: 549 thought tokens for a trivial prompt).
- The free tier also limits requests per minute per model, so speed alone is not enough: the
  first lite-model run stalled after 6 fast steps until pacing was added.

## Decision
- Analyst, Builder, Tester: `gemini-3.5-flash-lite`, fallback chain `gemini-3.1-flash-lite`, then
  `gemma-4-31b-it`.
- Reviewer: `gemini-3-flash-preview` (thinking model), fallback `gemini-3.5-flash`.
- A 503 gets one quick retry and then falls through to the next model; a 429 honours the server's
  `retryDelay`; a per-day quota error falls through immediately. The client paces itself to one call
  per ~4.5 s per model (free tier ~15 RPM).
- The model that actually served each call is logged in the transcript, and token counts per model
  in `usage.json`, so a fallback is visible in the results instead of silent.

## Alternatives considered
- **Keep Gemma, raise timeouts.** Keeps the open-weights story, but makes every run 20-40 min and
  hostage to 503s; it would not let us collect the five runs plus experiments. Rejected.
- **`gemini-3-flash-preview` for every role.** Stronger workers, but then Builder and Reviewer
  share one model (weakens ADR-008) and one per-minute quota. Rejected.
- **Reviewer on the lite model, workers on Flash.** Puts the strength in generation rather than
  verification; seeded-PR results (E1) are what tells us whether the reviewer is good enough, and
  a weak reviewer is the more dangerous failure. Rejected.

## Consequences
- Builder and Reviewer are still different models, and now also different tiers: the reviewer
  thinks before answering, the workers do not. ADR-008's independence argument still holds.
- Lite workers make more format and reasoning slips; the code gates (ADR-007) and retry budgets
  absorb them, at the cost of more calls.
- Lesson recorded: model choice for an agent pipeline is an availability and quota decision as much
  as a capability one; ADR-006 reasoned only about capability and independence.
