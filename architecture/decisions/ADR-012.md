# ADR-012: The reviewer's evidence must be grounded in what it actually executed, and its output contract is enforced in the loop

**Status:** Accepted (2026-11-21). Amends the evidence-gate part of [ADR-008](ADR-008.md) and [ADR-007](ADR-007.md)
(stage 6 check). ADR-008's other decisions (separate job, different model, withheld artifacts) stand.

## Context
ADR-008 introduced an evidence gate: an approval needs at least one executed command, and a finding without
evidence is dropped. Experiment E1 (seeded PRs, full reviewer) and the first real runs showed three gaps:

1. **Approval with zero commands (PR #9, first run).** The reviewer approved after only reading code. The gate
   caught it, but only *after* the agent had finished, so the review was wasted (`invalid`).
   Fixed during the run (commit "enforce reviewer evidence gate inside the loop"): `finish` with an approval and no
   executed command is now **refused inside the loop**, and the reviewer is told to go and run something.
2. **Hollow evidence (S5, PR #10).** The reviewer named the right defect (shallow copy leaks nested mutation), and
   its evidence said "Probe script output showing nested field mutation leaking …". But the only command it ran was
   `python -m pytest -q tests` (227 passed). The evidence was *asserted*, not produced. The gate accepted it because it
   only checked that evidence text was non-empty.
3. **Missing verdict (S3, PR #8).** The reviewer found the exact defect (exclusive bounds) with six executed
   commands and a real probe, but its `finish` had no `verdict:` line. The harness correctly marked it `invalid`.
   In the pipeline, that would have meant a wasted review round on a correct finding.

The common cause: the gate checked the *form* of the review after the fact, not its *grounding*, and not inside the
loop where the agent can still fix it.

## Decision
- A finding is kept only if its evidence is **grounded**: it quotes an existing `tinydb|tests/<file>.py:<line>`, or
  it shares a 24-character span with an executed command or its captured output (`gates.grounded`). Everything else
  is dropped, and the review notes how many findings were dropped and why.
- The reviewer's output contract is enforced **inside the loop** by the `finish` guard: no `verdict:` line, or an
  approval with no executed command, means the `finish` is refused with an instruction, and the agent continues
  (it is still bounded by its step cap).
- The reviewer prompt now says that evidence must be a pasted line of real output or an exact `file:line`.

## Alternatives considered
- **LLM judge for evidence quality.** Another model call that can be fooled in the same way. Rejected: grounding is
  checkable by string matching against the harness's own record of what ran.
- **Require a probe script for every finding.** Too strict for approach-level findings, which are often best
  evidenced by a `file:line` (e.g. "OR is made non-cacheable at queries.py:131"). Rejected in favour of either/or.
- **Leave the gate as is and rely on the reviewer being right.** In S5 the reviewer happened to be right. A gate that
  passes hollow evidence when the reviewer is right will also pass it when the reviewer is wrong. Rejected.

## Consequences
- A reviewer can no longer launder a guess into a "finding with evidence". A real finding with sloppy evidence is
  now dropped, which may turn a correct `changes_requested` into `approve_by_default`. That is a false negative we
  accept in exchange for no ungrounded rejections. It is visible in `review.md`.
- Grounding by 24-character overlap is a heuristic: a reviewer could paste unrelated output. It raises the cost of
  hollow evidence; it does not prove relevance.
- Evaluation: S5 (full reviewer) is re-run under this ADR and reported next to the original in E1.
